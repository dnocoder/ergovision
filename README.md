# ErgoVision

AI-система анализа посадки пользователя за компьютером.

Проект находится на начальной стадии: сейчас сформулирована идея, определены роли, MVP, план разработки и подход к оценке AI-компонента. Репозиторий пока используется как рабочая папка для подготовки структуры проекта.

## Project Brief

| Поле | Описание |
|---|---|
| Название проекта | ErgoVision |
| Проблема | Пользователи часто проводят много времени за компьютером и не замечают, что сидят с наклоненной головой, перекошенными плечами или слишком близко к экрану. Это может приводить к усталости, дискомфорту и снижению концентрации. |
| Целевая аудитория | Студенты, разработчики, офисные сотрудники и другие пользователи, которые долго работают за компьютером. |
| Пользовательский сценарий | Пользователь открывает web-приложение, разрешает доступ к камере, проходит короткую калибровку нормальной посадки, после чего система показывает текущий уровень риска и отдельные метрики позы. |
| Задача ИИ | Определить ключевые точки тела на изображении с камеры и на их основе оценить признаки неправильной посадки. |
| Почему без ИИ хуже | Без AI можно использовать только ручные напоминания по таймеру. Такая система не понимает реальное положение пользователя и не может оценить, есть ли проблема в текущий момент. |
| Тип AI-адаптации | CV / computer vision pipeline на основе pose-estimation модели и собственных правил оценки признаков. |
| Baseline | Простая система напоминаний по времени без анализа изображения. |
| Improved version | Анализ позы в реальном времени по keypoints: голова, плечи, расстояние до камеры, стабильность позы. |
| Целевые метрики | Accuracy, Precision, Recall, F1, latency, доля корректно обработанных кадров. |

## УТП

ErgoVision отличается от обычных reminder-приложений тем, что реагирует не по таймеру, а на фактическое положение пользователя перед камерой. Система не хранит видео и не отправляет изображение на сервер: анализ планируется выполнять локально в браузере.

## Планируемый MVP

MVP - минимальный набор функций, достаточный для демонстрации преподавателю:

- получение изображения с веб-камеры;
- определение ключевых точек тела через pose-estimation модель;
- расчет 3-4 признаков посадки;
- итоговый risk score от 0 до 100;
- экран с камерой, текущими метриками и статусом позы;
- небольшой eval-set для проверки качества.

## AI-компонент

Планируется использовать готовую pose-estimation модель:

- MediaPipe Pose;
- TensorFlow.js MoveNet;
- либо другую модель, которая стабильно работает в браузере.

Модель возвращает координаты ключевых точек тела. После этого система рассчитывает собственные признаки:

| Признак | Что показывает |
|---|---|
| Наклон головы | Отклонение головы от нормального положения |
| Наклон плеч | Разница высоты левого и правого плеча |
| Смещение головы | Положение головы относительно центра плеч |
| Расстояние до камеры | Слишком близкое положение пользователя |
| Стабильность позы | Изменение положения за последние кадры |

Итоговый результат - `riskScore` от 0 до 100:

| Диапазон | Интерпретация |
|---|---|
| 0-30 | Нормальная посадка |
| 31-60 | Средний риск |
| 61-100 | Высокий риск |

## Baseline и Improved

| Версия | Описание |
|---|---|
| Baseline | Таймер, который периодически напоминает пользователю проверить посадку. Изображение не анализируется. |
| Improved | AI-модуль анализирует keypoints пользователя и показывает предупреждение только при наличии признаков неправильной посадки. |

Такое сравнение позволит показать, что AI-компонент добавляет реальную пользу: система становится контекстной и реагирует на состояние пользователя, а не просто на время.

## Метрики качества

Планируемые метрики для оценки:

| Метрика | Что измеряет |
|---|---|
| Accuracy | Доля правильно классифицированных тестовых сценариев |
| Precision | Насколько часто предупреждение действительно соответствует неправильной посадке |
| Recall | Насколько часто система находит неправильную посадку |
| F1 | Баланс между Precision и Recall |
| Latency | Задержка обработки одного кадра |
| Success rate | Доля сценариев, где камера и модель отработали без ошибки |

Дополнительно можно фиксировать:

- средний `riskScore` за сессию;
- максимальный `riskScore` за сессию;
- долю кадров с высоким риском;
- количество ложных предупреждений.

## Eval-set

Для проверки планируется собрать минимум 20 тестовых примеров. Это могут быть короткие записи, фотографии или заранее воспроизводимые сценарии перед камерой.

| Сценарий | Описание |
|---|---|
| Normal | Пользователь сидит ровно |
| Head tilt | Голова наклонена в сторону |
| Head forward | Пользователь выдвигает голову вперед |
| Shoulder tilt | Одно плечо выше другого |
| Too close | Пользователь находится слишком близко к камере |

Для каждого примера будет задан ожидаемый класс. Затем результат системы сравнивается с ручной разметкой.

## Анализ аналогов

На следующем этапе планируется сравнить проект с прямыми и косвенными аналогами.

| Аналог | Что умеет | Где использует ИИ | Сильные стороны | Слабые стороны | Чем мы отличаемся |
|---|---|---|---|---|---|
| Posture reminder apps | Напоминания по таймеру | Обычно не используют | Простые и понятные | Не анализируют реальную позу | Реакция на фактическое положение пользователя |
| Webcam posture tools | Анализ позы через камеру | Computer vision | Близкая предметная область | Часто закрытый код или desktop-only | Web-first MVP и локальная обработка |
| Fitness pose apps | Анализ упражнений | Pose estimation | Хорошо работают с keypoints | Не ориентированы на работу за компьютером | Метрики адаптированы под посадку за столом |

## Предварительная архитектура

```text
src/
  ai/
    poseModel.ts          # загрузка и запуск pose-estimation модели
    postureMetrics.ts     # расчет признаков посадки
    riskScoring.ts        # расчет итогового risk score
  components/
    CameraPanel.tsx       # работа с камерой
    MetricsPanel.tsx      # отображение текущих метрик

    SessionChart.tsx      # график изменения состояния
    HistoryPanel.tsx      # история сессий
  storage/
    sessionStore.ts       # локальное хранение результатов
  types/
    pose.ts               # типы keypoints и метрик
  pages/
    Dashboard.tsx         # основной экран приложения
```

## Стоимость

На этапе MVP проект можно реализовать почти без прямых расходов:

| Статья | MVP | Примечание |
|---|---:|---|
| Разработка | 0 BYN | Учебная работа команды |
| Frontend-хостинг | 0 BYN | Vercel / Netlify free tier |
| Backend | 0 BYN | На MVP backend не обязателен |
| База данных | 0 BYN | LocalStorage / IndexedDB |
